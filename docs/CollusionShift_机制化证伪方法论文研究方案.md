# CollusionShift：面向 LLM 多智能体合谋研究的机制化证伪方法

**从跨机制 Benchmark 升级为方法论文的研究方案**
内部讨论稿 v0.1｜2026 年 7 月 27 日

## 执行摘要

本文建议将 MultiAgent4Collusion 的后续框架方向收敛为 **CollusionShift**：一个用于审计并主动证伪 LLM 多智能体合谋实验结论的计算方法与实验系统。论文不再把“可切换推荐机制”“从相同 checkpoint 进行反事实分叉”或“自动优化攻击策略”作为创新，因为这些能力已分别被 PolicySim、POSIM、反事实社会仿真研究和多智能体攻击研究覆盖。

拟解决的核心问题是：给定一条由仿真得到的比较性结论，例如“封禁比降权更有效”或“共享反思比独立反思具有更高攻击收益”，能否在现实约束的平台机制空间内，自动找到**使结论反转的最小机制变化**，并给出该反例跨随机种子、模型家族和场景的稳定性证据。

论文的主要方法不是 Benchmark 本身，而是一个暂称 **ClaimFuzz** 的受约束结论证伪算法。它将研究结论编译为可计算的结论裕量，在离散—连续混合的平台机制空间中，以较少仿真调用寻找符号反转点，再沿反例边界搜索距离原始平台最近的可信反例。Benchmark 负责提供标准化的机制空间、待检验结论、训练—测试划分、基线和指标，用于验证 ClaimFuzz，而不是充当全部创新。

> **建议立项结论**：可以作为独立于白盒解释方向的方法论文候选，但必须先通过两周 go/no-go 预实验。若无法稳定观察到结论反转，或 ClaimFuzz 在相同预算下不能优于随机搜索和通用黑盒优化，应停止该方向，而不是继续扩大框架规模。

## 1. 研究定位与贡献边界

### 1.1 论文不再声称什么

以下能力可以实现，但不能单独作为核心创新：

- 在多个推荐算法或治理策略下重复仿真；
- 保存 checkpoint，并从相同状态运行不同干预；
- 用 LLM、强化学习或进化搜索自动生成攻击策略；
- 增加更多角色、画像、记忆、反思和共享反思；
- 支持更大规模的智能体或更多社交动作；
- 仅发布配置、数据集和评测榜单。

这些能力分别与 OASIS、MultiAgent4Collusion、MOSAIC、PolicySim、POSIM、MultiAttack 等已有工作存在显著重合。它们应作为基础设施或基线，而不是首创声明。

### 1.2 本文真正研究什么

本文把“一个仿真实验得到的结论是否稳健”本身作为研究对象。核心问题为：

1. **结论脆弱性**：合谋攻击和平台防御的比较性结论，在平台机制变化后是否发生反转？
2. **最小反例**：推翻一条结论所需的最小、现实合理的平台机制变化是什么？
3. **搜索效率**：能否用显著少于穷举的仿真次数找到并确认反例？
4. **跨环境稳定性**：反例能否跨随机种子、LLM 家族、话题和网络拓扑复现？
5. **结论成立域**：一条结论在哪些机制条件下成立，在哪些条件下失效？

### 1.3 与白盒解释方向的边界

CollusionShift 是独立的框架/方法方向。它只需要读取攻击、防御和平台结果，不要求使用白盒检测器、SHAP、双曲解释或实时证据。白盒方法未来可以作为一种待审计防御接入，但不是本论文成立的前提。

## 3. 问题形式化

### 3.1 基本对象

设：

- \(m \in \mathcal{M}\) 为平台机制配置，包括推荐、曝光、传播摩擦、身份和治理规则；
- \(m_0\) 为产生原始研究结论的基准机制；
- \(S(m, \pi_A, \pi_D, z)\) 为仿真器，其中 \(\pi_A\) 是合谋攻击策略，\(\pi_D\) 是防御策略，\(z\) 包含初始状态、随机种子、模型与场景；
- \(J(\pi_A, \pi_D; m, z)\) 为结果效用，例如有害曝光、任务完成率、正常用户效用或综合安全收益；
- \(C\) 为待检验的比较性结论。

例如“防御 A 优于防御 B”可写为结论裕量：

\[
g_C(m,z) = J(\pi_A, \pi_{D=A};m,z)-J(\pi_A, \pi_{D=B};m,z).
\]

若在基准机制中 \(g_C(m_0)<0\) 表示 A 的有害曝光更低，而在新机制中 \(g_C(m)>0\)，则结论发生反转。

### 3.2 机制距离

为了避免找到极端但没有解释价值的配置，定义机制距离：

\[
D(m,m_0)=\sum_k w_k d_k(m_k,m_{0k}),
\]

其中连续参数使用归一化距离，类别机制使用带语义权重的切换成本，结构性变化可使用图或规则编辑距离。权重 \(w_k\) 来自公开平台规则、相关文献或专家约束，而不是为得到理想结果任意调节。

### 3.3 可信反例

机制配置 \(m^*\) 只有满足以下条件才被接受为可信反例：

1. \(m^*\) 位于预先定义的现实可行域 \(\mathcal{M}_{plaus}\)；
2. 结论符号相对于 \(m_0\) 发生反转；
3. 反转在预设数量的随机种子上达到统计置信要求；
4. 至少跨两个模型家族或两个独立场景复现；
5. 平台机制执行日志证明变化确实经过推荐、曝光或治理链路产生影响；
6. 不依赖标签泄漏、私有攻击提示或不现实的防御信息。

目标问题为：

\[
m^*=\arg\min_{m\in\mathcal{M}_{plaus}}D(m,m_0)
\quad \text{s.t.}\quad
P\left[g_C(m)g_C(m_0)<0\right]\ge 1-\alpha.
\]

这是一个带统计确认、现实约束和昂贵黑盒函数的离散—连续混合优化问题。

## 4. 方法：ClaimFuzz

### 4.1 方法总览

ClaimFuzz 接收一条结论、基准实验和机制空间，输出最小可信反例、结论成立域和搜索审计记录。

**处理链路**：

1. **Claim Compiler**：把自然语言研究结论转换为策略对、指标、方向和统计判据；
2. **Mechanism Schema**：定义机制变量、范围、依赖关系、现实约束和距离；
3. **Paired Executor**：从相同 checkpoint 对候选机制进行配对仿真；
4. **Claim-Margin Estimator**：估计 \(g_C(m)\)、方差和反转概率；
5. **Budget-aware Search**：在仿真预算内选择最有希望的下一机制；
6. **Boundary Refiner**：在已发现反例附近寻找距离更小的边界点；
7. **Confirmation Runner**：增加种子、规模、模型和场景确认；
8. **Audit Reporter**：输出最小反例、成立域、失败域、证据和复现配置。

### 4.2 两阶段搜索

#### 阶段 A：低成本反例发现

- 使用少量空间填充样本覆盖主要类别机制；
- 在较小规模和较短时域下运行低保真仿真；
- 训练结论裕量代理模型 \(\hat g_C(m)\)；
- 通过下式选择候选：

\[
a(m)=\frac{P(\text{sign flip}\mid m)\cdot U(m)}{D(m,m_0)+\lambda\,Cost(m)},
\]

其中 \(U(m)\) 表示不确定性或信息增益，\(Cost(m)\) 表示仿真成本。该获取函数优先选择反转概率高、距离近、信息增益大且成本低的机制。

#### 阶段 B：边界细化与高保真确认

- 对已找到的反例执行局部邻域搜索；
- 逐步撤销或缩小机制变化，逼近最小反例；
- 在 N=500/1000、T=30/50 和更多随机种子下复跑；
- 更换模型家族与话题，确认不是单模型或单提示现象；
- 使用顺序检验或预设置信区间决定接受、拒绝或继续采样。

### 4.3 混合机制编码

平台机制同时包含：

- 类别变量：推荐器类型、治理层级、身份恢复规则；
- 连续变量：探索比例、热度权重、速率限制、重注册成本；
- 条件变量：只有启用群体治理后才存在群体阈值；
- 组合约束：某些推荐器与曝光规则不能同时启用。

第一版可采用分层编码和树结构搜索：先选择结构机制，再优化其连续参数。正式论文应与随机搜索、网格/分数因子设计、通用贝叶斯优化和进化搜索进行等预算比较。

### 4.4 方法输出

对每条结论，ClaimFuzz 输出：

- 基准机制与原始结论裕量；
- 最小可信反例及机制距离；
- 反例确认所用的种子、模型、场景和置信区间；
- 结论成立域与失效域；
- 关键机制及交互效应；
- 搜索轨迹、累计仿真成本和失败候选；
- 可直接复现的配置与 checkpoint 哈希。

## 5. Benchmark 的角色

Benchmark 是 ClaimFuzz 的验证载体，而不是论文的全部贡献。它需要包含：

### 5.1 待检验结论集

首批结论可以来自原框架和常见研究假设：

- 去中心化合谋比中心化合谋更难治理；
- shared reflection 比独立 reflection 带来更高攻击收益；
- 封禁比内容降权更有效；
- 跨社区桥接比短时集中放大具有更高长期传播收益；
- 群体级治理比单账号治理具有更低的正常用户损失；
- 某一治理策略在固定成本下具有最优安全—效用权衡。

结论必须预注册指标方向和比较条件，不能看完结果后再改变定义。

### 5.2 平台机制空间

建议第一版使用四个主要维度：

1. **推荐机制**：时间序、热度、个性化、多样性/探索推荐；
2. **曝光结构**：关注网络优先、跨社区探索、全局热榜；
3. **传播摩擦**：限频、集中互动折损、转发确认或传播延迟；
4. **身份与治理**：重注册成本、内容降权、账号治理、群体协同降权。

干预是平台级或批量策略，可同时影响大量账号，不采用“平台每轮只能处理一个账号”的不现实设定。

### 5.3 机制泛化划分

- **ID**：机制类型和参数范围均已见；
- **Parameter-OOD**：机制类型已见，但参数范围未见；
- **Compositional-OOD**：组件已见，但组合未见；
- **Structural-OOD**：出现训练中不存在的机制类别；
- **Model/Scenario-OOD**：更换模型、话题、初始网络和攻击比例。

## 6. 系统重构方案

### 6.1 当前可复用能力

现有仓库已经具备：

- Twitter/Reddit 风格平台与多种社交动作；

### 6.3 必须保证的状态完整性

checkpoint 需要保存智能体记忆、反思、共享内存、任务黑板、帖子与互动、推荐缓存、关注图、账号状态、平台时钟、随机数状态、模型配置和输入哈希。若只复制数据库而遗漏 LLM memory 或随机数状态，就不能声称从相同状态进行配对比较。

## 7. 实验设计

### 7.1 研究问题

- **RQ1**：现有合谋攻击与防御结论在平台机制变化下有多脆弱？
- **RQ2**：ClaimFuzz 能否以更少仿真调用找到更近、更稳定的反例？
- **RQ3**：反例是否跨随机种子、模型家族、话题和网络拓扑成立？
- **RQ4**：多机制训练或机制随机化能否降低攻击/防御的最坏情况后悔值？
- **RQ5**：哪些机制及其交互作用最常导致结论反转？

### 7.2 攻击与防御条件

攻击至少覆盖：

- 短时集中放大；
- 跨社区桥接传播；
- 长期潜伏/分阶段传播；
- 原生 reflection 与 shared reflection；
- 可选：自动策略搜索或 MARL 作为强基线。

防御至少覆盖：

- 无治理；
- 内容级降权/标注；
- 平台级传播摩擦；
- 账号封禁及不同重注册成本；
- 群体协同降权，但不依赖白盒解释。

### 7.3 规模与重复

| 阶段 | 设置 | 用途 |
|---|---|---|
| 冒烟 | N=30，T=5，1–2 seeds | 状态恢复、机制生效、日志校验 |
| 立项预实验 | N=100，T=20，3 seeds，2 模型家族 | 判断是否存在稳定反转和搜索优势 |
| 主实验 | N=500/1000，T=30/50，关键条件≥5 seeds，3 模型家族 | 论文结论与统计检验 |
| 扩展性 | N=2000/5000，T=30，少量条件 | 运行成本与系统吞吐，不承担主要因果结论 |

为控制成本，可以让关键恶意智能体和抽样正常用户使用 LLM，其余正常用户使用经校准的轻量代理；必须在小规模全 LLM 实验上验证这种替代不会改变结论排名。

### 7.4 方法基线

- Random Search；
- Grid/Fractional Factorial Search；
- 通用 Bayesian Optimization；
- Evolutionary Search；
- 无边界细化的 ClaimFuzz；
- 无机制距离约束的 ClaimFuzz；
- 单保真与多保真版本；
- Oracle/Exhaustive，仅在极小机制空间中作为上界。

### 7.5 主要指标

**方法指标**：

- 首个确认反例所需仿真调用数；
- 最小反例机制距离；
- 反例确认率与假反例率；
- 单位计算成本的反例发现率；
- 结论边界估计误差；
- 相对于穷举的覆盖率。

**安全与泛化指标**：

- Attack Transfer Ratio；
- Defense Regret 与 Worst-case Regret；
- Rank Inversion Rate；
- Kendall’s \(\tau\) 排名一致性；
- 有害曝光、传播深度、任务完成率；
- benign utility loss 与误伤率；
- 机制因素主效应和交互效应。

### 7.6 统计要求

- 报告均值、置信区间、效应量，而不只给最佳数值；
- 使用配对设计和相同初始状态降低方差；
- 用混合效应模型区分机制、模型、场景和随机种子的影响；
- 对多条结论和多次搜索进行多重比较校正；
- 在正式实验前冻结主要结论、指标和停止规则；
- 单独报告未复现反例和失败搜索，避免选择性呈现。

## 8. 仿真有效性与可信度

### 8.1 三层验证

1. **机制层**：验证推荐、曝光、摩擦、身份和治理插件确实按照定义改变平台事件流；
2. **个体层**：检查动作频率、内容类型、角色异质性、同义扰动稳定性和提示泄漏；
3. **群体层**：检查级联规模、深度、持续时间、网络结构和时间分布是否与真实数据或已知规律相符。

### 8.2 真实数据的用途

TwiBot 数据可以用于账号画像、机器人比例和网络统计校准，但不足以单独验证完整传播与曝光过程。建议补充包含新闻传播或谣言级联的数据，例如 PHEME/CoPHEME、FakeNewsNet 或其他许可明确的数据。真实数据用于校准基准机制和验证观测统计，不能证明未部署干预的真实因果效果。

### 8.3 结论范围

论文应把结果描述为：

> 在经过指定层级校准的模拟器与机制空间中，某条结论对哪些平台机制变化稳健或脆弱。

不能直接写成：

> 真实平台采用某政策一定会产生相同结果。

## 9. 两周 Go/No-Go 预实验

### 9.1 最小实现

- 3 种推荐机制；
- 2 种传播摩擦或身份规则；
- 3 种攻击策略；
- 3 种防御；
- N=100、T=20、3 seeds；
- 2 个固定版本的开源模型家族；
- Random Search 与 ClaimFuzz 最小版本；
- 完整 checkpoint 和 paired runner。

### 9.2 继续立项的门槛

以下四项至少满足前三项：

1. 至少两条预注册结论出现可重复的机制反转；
2. 反转在两个模型家族或两个场景中仍成立；
3. 排除提示泄漏、随机异常和机制未生效；
4. ClaimFuzz 在相同调用预算下，比 Random Search 更快找到确认反例，或找到机制距离显著更小的反例。

### 9.3 停止条件

出现以下任一情况应停止或重新选题：

- 结论在合理机制空间内几乎不发生反转；
- 反转只存在于极端、不可信配置；
- 反转主要由单一模型或提示措辞造成；
- ClaimFuzz 与通用优化方法没有稳定差异；
- checkpoint 无法完整恢复，配对实验存在系统性偏差；
- 所需计算预算超过团队可承受范围且轻量代理无法保序。

## 10. 论文贡献的推荐写法

若实验成功，贡献可写为：

1. **问题贡献**：提出 LLM 多智能体合谋实验的机制稳健性审计问题，将单环境结果从“结论”降格为需要检验的假设；
2. **方法贡献**：提出 ClaimFuzz，在现实约束、混合机制和有限仿真预算下搜索使比较性结论反转的最小机制变化；
3. **系统贡献**：实现可组合机制、完整 checkpoint、配对执行、多保真搜索和跨模型确认的一体化证伪系统；
4. **实证贡献**：系统测量攻击迁移、治理排名反转和最坏情况后悔值，识别稳健规律与机制特定规律；
5. **资源贡献**：发布结论集、机制空间、运行日志、复现配置和机制稳健性 Benchmark。

其中第 2 和第 4 项必须成立，否则论文会退化为普通 Benchmark 或工程框架。

## 11. 投稿定位

- **WWW / ICWSM**：首选，适合平台机制、社会计算、安全风险与实证审计；
- **AAMAS**：ClaimFuzz 的搜索、博弈或多智能体方法需要更强算法深度；
- **KDD**：需要更强的数据规模、方法性能和真实数据验证；
- **ACL / EMNLP**：仅当语言智能体行为建模或语言层泛化成为核心；
- **CCS / USENIX Security**：仅有合成仿真通常不足，需要真实威胁模型、系统验证和可操作防御。

建议优先按 WWW/ICWSM 风格组织：问题清晰、平台意义明确、方法可复现、实证发现扎实，并严格限制真实世界因果主张。

## 12. 执行计划与交付物

### 阶段 0：立项核验（2 周）

- 形成至少 20 篇近邻工作的 claim–method–experiment 矩阵；
- 完成机制 schema、checkpoint、paired runner；
- 实现 ClaimFuzz 最小版本与随机搜索；
- 跑完 go/no-go 实验并形成决策记录。

### 阶段 1：方法与框架（3–4 周）

- 完成混合机制搜索、多保真、边界细化和统计确认；
- 完成运行目录、manifest、哈希与失败恢复；
- 建立机制验证和轻量代理保序测试。

### 阶段 2：主实验（3–5 周）

- 完成主要结论集、机制划分和基线；
- 运行跨规模、模型、场景和随机种子实验；
- 生成结论成立域、失效域和搜索效率曲线。

### 阶段 3：论文与开放资源（2–3 周）

- 冻结代码、配置、数据和统计脚本；
- 完成方法、实验、限制、伦理和复现章节；
- 从干净环境复跑最小实验；
- 发布匿名仓库或补充材料。

## 13. 主要风险

| 风险 | 具体表现 | 缓解方案 |
|---|---|---|
| 创新撞车 | 新论文出现相同的自动反例搜索 | 持续维护相关工作矩阵；避免未经核验的首次主张 |
| Benchmark 化 | 只有机制切换和榜单，没有方法优势 | ClaimFuzz 必须在效率、距离或确认率上显著优于基线 |
| 真实性不足 | 反例来自不可信平台配置 | 预定义现实可行域、机制距离与真实统计校准 |
| LLM 随机性 | 反转无法跨模型或种子复现 | paired design、顺序确认、固定开源模型版本 |
| 计算成本 | 大规模搜索调用过多 | 多保真搜索、缓存、轻量代理与小规模边界发现 |
| 结论泄漏 | 看到结果后修改指标或结论 | 预注册结论、指标、方向和停止规则 |
| 双重用途 | 输出过度具体的攻击操作方案 | 发布机制级规律和聚合策略，不发布真实平台可直接执行的攻击脚本 |

## 14. 最终决策建议

本方向可以继续，但需要采用以下唯一主叙事：

> **CollusionShift 不只是一个跨机制 Benchmark，而是一种面向 LLM 多智能体合谋研究结论的机制化证伪方法。它在现实约束的平台机制空间中，以有限预算寻找推翻比较性结论的最小机制反例，并输出结论成立域和失效边界。**

Benchmark、checkpoint、机制插件和批量仿真都是为这一方法服务的基础设施。若两周预实验无法证明“结论确实会在合理机制下反转”以及“ClaimFuzz 比通用搜索更有效”，则不应继续投入完整论文周期。
